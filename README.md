# ds-port · DeepSeek 会话搬运

为使用deepseek手机端做饭的everybody提供（本人就是）。
把一条 DeepSeek 分享链接，变成一段可以粘进新会话的提示词，让新对话接得上旧对话的语气和处境。

> **这不是破解限流。** 它只读取你自己已经公开分享出去的链接，把里面你写过的内容换个位置接着用。不登录、不带 cookie、不向 DeepSeek 写入任何东西。

## 为什么需要它

z最近ds手机端“算力不足”所以限制了用户端，手机端一个会话聊到一定长度、或者沉寂几天之后就没法继续了。但分享链接还在，内容还在。丢掉可惜，重开一个又不像——语气、称呼、写惯了的小动作全得重来。

这个工具解决的就是这件事：把旧会话压缩成一份「设定 + 时间线 + 写法 + 最近原文」的提示词，新会话读完就能接着写。

## 怎么用

需要 Python 3.9+，**不用装任何依赖**。

```bash
python server.py
# 打开 http://127.0.0.1:8899
```

粘链接 → 选参数 → 点「读取并生成」→ 复制提示词。

也可以走命令行，直接生成文件：

```bash
python cli.py "https://chat.deepseek.com/share/xxxxxxxx" -o prompt.txt
python cli.py "链接1 链接2" --merge --budget 8000
```

## 保真的三层

不做「总结剧情」——总结会把语气洗掉，新会话第一句就不像了。所以分三层处理：

| 层 | 内容 | 处理方式 |
|---|---|---|
| 设定卡 | 第一条长文用户消息 | **逐字原样**，一字不改 |
| 最近 N 轮 | 默认最后 12 轮 | **逐字原样**，连括号、错字、语气词都留 |
| 中间历史 | 更早的轮次 | 一行一轮的时间线，保事件顺序不保文采 |

提示词的结构：

1. 开头一句：读完直接进入角色，从最后一行接着写，不要复述、不要总结
2. **你是谁** —— 设定卡原文
3. **已经发生过的事** —— 按日期分段的时间线
4. **当前状态** —— `【占有欲：100】` 这类标记的当前值和出现次数
5. **写法** —— 全部从原文统计出来（字数区间、高频词、动作起手、语气样本、内心独白样本）
6. **最近 N 轮原文** —— 逐字
7. **现在开始** —— 接最后一句往下写

### 一条容易漏、漏了就废的覆盖

设定卡里常写着「你的第一条回复必须从当前剧情开始：……」这类开场指令。如果不在提示词里显式压掉它，新会话会从第一天的场景重新开机，前情全废。所以「写法」一节的第一条专门处理这个。

### 写法一节是统计出来的，不是套话

- 字数区间 = 角色回复中位数 × 0.6 ~ × 1.8，十位取整，最低 40 字
- 惯用说法 = 对角色回复做 2–4 字 n-gram 统计，`词频 × 字长` 排序，出现 ≥3 次才入选，再滤掉代词、助词、语法碎片
- 动作起手词 = 每个 `（…）` 去掉主语后的头 2–6 字
- 语气样本 = 沿时间轴在 1/4、2/4、3/4 处各取一条长度接近中位数的，避免只学到结尾画风

## 预算控制

可选 8000 / 16000 / 30000 / 不限。超了按这个顺序削，并在界面上告诉你削了什么：

1. 语气样本减到 1 条
2. 时间线从最早的开始，每次砍前 1/10
3. 最近原文减半（不低于 6 轮）
4. 时间线压到最近 60 条

**设定卡和最后一轮永远不削。**

## 目录

```
ds-port/
├─ server.py          本地服务（http.server），只监听 127.0.0.1
├─ fetcher.py         分享链接 → 规范化消息；含缓存、重试、限流处理
├─ builder.py         规范化消息 → 提示词（核心）
├─ cli.py             命令行入口
├─ static/index.html  界面，单文件内联，无框架无 CDN
├─ smoke_test.py      离线自检（不联网）
└─ cache/             抓到的原文，按 share_id 存，24 小时过期
```

## 隐私

- 只请求 `chat.deepseek.com` 的公开分享接口，只带一个普通浏览器 UA
- 不登录、不带 cookie、不写任何东西回去
- 抓到的原文缓存在本机 `cache/`，一天后过期；`cache/` 已在 `.gitignore` 里，不会被提交
- 服务只监听 `127.0.0.1`，局域网里别的机器访问不到

## 已知限制

- 分享被删除或设为私密时，接口返回 `biz_code != 0`，界面会给一句人话错误，不白屏
- 消息 id 可能有空洞（删过、重新生成过），这是正常的，不做补齐
- 多份分享合并时，接缝处会去重；如果接缝出现连续两段「我」的发言，会提示可能不是同一条时间线
- `title` 字段分享页固定返回 `Shared Conversation`，所以角色名靠正文推断，推不出来时用「角色 / 你」兜底，可以在界面上手动覆盖

## 自检

```bash
python smoke_test.py
```

不联网，用合成数据验证：链接提取、消息规范化、设定卡识别、节编号、最近原文不和开场重复、预算削减。
